# Factory execution profiles

[Taskbot #57](https://taskbot.apps.janjaap.de/p/bobs-factory/t/57) adds versioned execution identities and tool profiles to Recipes, independent composer selectors, effective preview and saved run details. No profile metadata means **Legacy** execution. Explicit profiles resolve credential references into private per-root/per-job environments; selecting tools does not select an account. Configure both concerns before enabling a profile launch.

## Implemented contract

New admissions select each concern independently: manual choice → repository default → factory default → Legacy. Accepted definitions and references survive profile edits/deletion, nested graphs, fanout, title jobs, Simple, follow-ups and restart. Recovery revalidates the saved principal and resource version rather than adopting new defaults. The editor saves atomically with revisions and retains drafts on conflicts. Active consumers are listed before changes.

The composer retains explicit identity and tool profile IDs in tab-local session storage across reloads and application updates. It stores no resolved configuration or credentials. Clearing either choice restores default resolution independently; preview results must be checked again after a reload.

Share reads declared sources at each operation. Overlay privately snapshots declared JSON source files and applies object overlays. Factory-only uses explicit definitions. API credential references remain separate from ordinary settings and MCP definitions. MCP definitions replace whole servers; removal tombstones apply last. `factory-context` remains runtime-owned and role permission restrictions remain authoritative.

Secrets are excluded from public profile definitions, API/SSE, transcripts, outputs and activity logs. Credential versions are pinned by private digests; repository tokens may rotate only when the accepted principal still matches. This boundary controls cooperating tools' configuration. It does not prevent same-user code from reading host files; existing sandbox/permission restrictions still apply.

Transient generated private auth caches are removed when a graph settles and are rematerialized from accepted resources for resume. Private runner state and source snapshots remain outside worktrees and public evidence, with owner-only directories/files. Owned project artifacts are restored on completion, stop and dead-process recovery. Resume retains its authorized state and accepted bindings. Operators must not delete private snapshots while consumers need recovery.

Native Share validates the existing account without starting a model turn and suppresses competing API environment variables. Credentials are neither copied nor pinned by their refreshable token values. Resume validates the same root and account again; changing the account requires a new admission. Cleanup never removes credentials from the selected host root. Claude native Share retains the original HOME because default login metadata lives in `~/.claude.json` beside the selected default `~/.claude` directory; custom roots use `CLAUDE_CONFIG_DIR`. Git/provider configuration stays explicitly scoped. Native CLI refresh and session-state writes use that original store, so Share is explicitly a shared mutable resource, not private state. Tool Share still uses declared sources and strict selected MCP, rather than enabling arbitrary host discovery. Native login with Overlay or Factory-only tools rejects before setup.

Official lookup contracts: [Claude configuration roots](https://code.claude.com/docs/en/settings) and [Codex login caching and stores](https://developers.openai.com/codex/auth/). The installed native CLIs remain the capability gate.

## Supported-mode contract and guaranteed MVP

The following describes **what this implementation must deliver**, not existing functionality. Each concern chooses its policy independently:

- **Share:** explicitly inherit the named host source/resource. Ordinary allowed files are read at process/operation start; the service environment is its startup snapshot, not a live interactive-shell environment.
- **Overlay:** snapshot allowed ordinary configuration at run admission, then apply factory overrides/removals. Credentials replace a selected binding; they are never recursively merged.
- **Factory-only:** only explicit factory configuration and allowed credential resources, with automatic host fallback suppressed. Repository instruction/code inputs remain available; this is not an OS sandbox.
- **Legacy:** absent profile metadata preserves current behavior, including runner-specific strict MCP defaults. Legacy is not equivalent to unrestricted Share.

All supported explicit modes retain managed policy. Incompatible managed enforcement, unsafe repository configuration or an unsupported transport fails preflight with the exact conflicting source and a supported alternative.

**Mandatory crossed combinations:** deliver and test both (1) factory Git/remote/signing and runner API identity with declared shared host MCP/tools, and (2) host Git/remote/signing and host runner API-key identity with factory-only MCP/settings. Claude and Codex are the unrestricted MVP reference adapters for these cases on eligible, nonconflicting configurations. Run the same cases for OpenCode; Gemini/Cursor support the clean-project restrictions above. These are acceptance requirements, not discretionary experiments. A tool-source change must never implicitly change account selection, and an identity-root change must not silently drop shared tools.

For host identity with private tool roots, resolve host credential references independently of HOME/config materialization: retain explicitly allowed SSH/GPG sockets or use the chosen host provider credential binding. The required cross-case does not depend on copying refreshable native OAuth stores. Native subscription login combined with factory-only tools is explicitly unavailable unless a separate supported binding exists; show this before Start.

Shared tools in the factory-only identity cross-case are declared MCP definitions and supported ordinary runner settings. Their authentication fields are separately resolved. Arbitrary plugins/scripts that introduce undocumented automatic credential lookup are not supported isolated-auth sources merely because they were installed on the host.
