# TUI Today inbox — mocked F1 drive

**Date:** 2026-10-09  
**Issue:** [Taskbot #114](https://taskbot.apps.janjaap.de/p/bobs-factory/t/114)  
**Tested implementation:** `08d89b16` (based on `3e117128`); the final evidence/changelog commit changes documentation only.  
**Agent mode:** mocked; no agent CLI or inference API was invoked.

## Applicability and scenario

The new terminal UI changes operator authentication, manual launch, question
submission and activity rendering. These are F1-covered workflows. The fixture
uses a real EdgeWorker, isolated Git repository/worktrees, FactoryServer,
filesystem-authorized terminal session, HTTP/SSE client and TodayApp. Only the
provider boundary uses `f1AgentHandlers("mock")`.

```sh
pnpm --filter bobs-factory-edge-worker build
pnpm --filter bobs-factory build
F1_AGENT_MODE=mock bun apps/f1/test-drives/assets/tui-inbox.ts
```

The fixture creates fresh state under the OS temporary directory and saves
`result.json` plus ANSI frames there. It stops the worker and terminal timers
after the run. `--serve` leaves only that isolated worker available for a separate
pseudo-terminal pass until SIGTERM/SIGINT; it never selects production state.

## Results

- Unauthenticated localhost API access returns 401; a private local terminal
  request authenticates the HTTP client and SSE connection.
- Keyboard launch uses the saved recipe default and creates an isolated worktree.
- Questions/recommendations appear through live updates; no answer is accepted
  until explicit keyboard submission.
- Ctrl-K filters and opens the selected run. Light/dark switching and a 60×16
  answer form retain readable context and a visible editing field.
- A custom answer reaches the question batch, resumes the mocked step and completes.
- The conversation displays the provider result and workflow completion.
- Settling removes the run from the open inbox; showing Settled and reopening it
  preserves its history and brings it back.
- A running script is stopped using the TUI's confirmation dialog and authenticated
  stop route. The resulting run status is `stopped`.

All assertions passed. A separate native pseudo-terminal pass exercised the CLI
entry point, automatic theme detection, theme toggle, new-run draft, Ctrl-K,
Escape, bracketed paste split across writes, and Ctrl-C exit (status 0).
Its ANSI frames were rendered for visual inspection of both themes; selected
rows use opposite-theme text/status colours on an inverted background.

## Other verification and limits

CLI suites: 14 files / 167 tests passed. Factory auth/access/server, web client
and questions suites: 5 files / 68 tests passed. Regression checks cover
fragmented keys/pastes, focused forms in short terminals, localhost-only
session authority, credential-management denial, logout/recovery/restart,
malformed request paths and preserved write-origin checks.

The repository pre-commit gates completed the full workspace build and type
checks. A native darwin-arm64 binary compiled from this implementation passed
isolated startup, dashboard assets, protected API, MCP, shutdown and restart smoke.

This drive proves mocked orchestration and terminal interaction. It does not
prove native provider output, external PR merge delivery, physical terminal
font behaviour, or browser passkey enrollment. Review and message APIs retain
their existing server tests; guided review stays in the browser.
